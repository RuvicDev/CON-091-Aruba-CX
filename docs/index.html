Conector Aruba CX — Guía de configuración

Última actualización: octubre 2026

¿Qué es y para qué sirve?

El conector Aruba CX permite que el agente de Ruvic consulte switches HPE Aruba CX: información general, interfaces, VLANs y el estado de un puerto. Es de solo lectura. Puedes pedirle cosas como:

  • "¿Qué puertos del switch core están caídos?"
  • "¿En qué VLAN está el puerto 1/1/24 y tiene errores?"
  • "¿Qué versión de firmware tiene el switch?"

Operaciones soportadas:

OperaciónQué hace
switch.infoHostname, plataforma, firmware y número de serie
interfaces.listInterfaces con estado administrativo, de enlace y velocidad
vlans.listVLANs configuradas
ports.statusEstado detallado y contadores de un puerto
Solo lectura El conector no cambia la configuración del switch. Usa un usuario del grupo operators.

Prerrequisitos

  • Switch HPE Aruba CX con AOS-CX 10.04 o superior y la API REST habilitada.
  • Acceso de administrador al switch para crear el usuario de solo lectura.
  • Conectividad HTTPS desde la plataforma Ruvic hasta la IP de gestión del switch.

Configuración en el fabricante

Vas a crear un usuario de solo lectura y habilitar la API REST en modo lectura.

  1. Crea el usuario de solo lectura.

    En la CLI del switch: user ruvic-api group operators password plaintext <contraseña>.

  2. Habilita la API REST.

    Ejecuta https-server rest access-mode read-only y https-server vrf mgmt (o el VRF de tu red de gestión).

    [ Captura: configuración https-server en la CLI — reemplazar por assets/img/arubacx-rest.png ]
  3. Comprueba la versión de la API.

    Abre https://<switch>/rest en el navegador y anota la versión más reciente (ej. v10.13).

Permisos requeridos

El grupo operators es suficiente: el conector solo lee.

PermisoPara qué lo usa el conector
group operatorsLeer sistema, interfaces y VLANs
https-server rest access-mode read-onlyPermitir la API REST sin escritura

Configuración en Ruvic

Entra a Settings → Conectores, busca la tarjeta Aruba CX y pulsa Configurar. Diligencia el formulario con los valores de la sección anterior:

Campo del formularioValor
URL del switchURL HTTPS de gestión del switch, ej. https://10.0.0.10
UsuarioUsuario del grupo operators
ContraseñaContraseña del usuario. Se guarda cifrada
Versión de la API RESTVersión de la API, ej. v10.13; por defecto v10.09
Verificar certificado SSLDesactívalo solo si el switch usa el certificado autofirmado de fábrica en una red de confianza
Timeout de conexión (segundos)Opcional; 15 segundos por defecto

Guarda y pulsa Probar conexión: la plataforma valida las credenciales y el acceso.

[ Captura: formulario del conector Aruba CX en Settings → Conectores — reemplazar por assets/img/aruba_cx-form.png ]

Verificación

  1. Test de conexión exitoso.

    El botón Probar conexión debe responder con éxito y la tarjeta debe quedar en estado Configurado.

  2. Prueba mínima con el agente.

    Abre una conversación nueva y pídele:

    "¿Qué puertos del switch están caídos?"

    El agente debe responder con la lista real de interfaces sin enlace.

Solución de problemas

Mensaje / síntomaCausa probable y solución
"Usuario o contraseña inválidos" (401)Revisa las credenciales del usuario local.
"La versión de API … no existe"Consulta https://<switch>/rest y usa una versión listada.
"límite de sesiones REST"Hay demasiadas sesiones abiertas para el usuario; expiran a los 20 minutos.
"Error de certificado SSL"El switch usa su certificado de fábrica. Instala uno válido o desactiva la verificación en una red de confianza.

Preguntas frecuentes y notas de seguridad

¿El agente puede apagar un puerto o cambiar una VLAN?

No. El conector es de solo lectura y el usuario recomendado no tiene permisos de escritura.

¿Puedo consultar varios switches?

Sí: crea una instancia del conector (alias) por switch.

¿Qué hago si la contraseña se filtra?

Cámbiala en el switch y actualízala en el formulario.
